# 复现日志

按时间顺序记录实际做过的事、遇到的阻塞、以及如何解决。
**包含失败与返工**——这些是复现工作量的主要部分。

## 阶段 0：环境

| 事实 | 结论 |
|---|---|
| 官方 `pcfm_env.yml` 锁定 python 3.10.14 / torch 2.4.1 / neuraloperator 0.3.0 | 与本机 python 3.13 + torch 2.10 不兼容，不能照装 |

- 曾试图降到 0.3.0，失败：该版本无 `requires_python` 约束，依赖链拉不动
- 最终改 1 行调用（见 `THIRD-PARTY.md`）

## 阶段 1：确认官方代码的缺口

对上游仓库做了穷尽检索，发现**推理装配层整体缺失**：

| 检索 | 结果 |
|---|---|
| `Residuals(` | 全仓 **0 处实例化** |
| `class X(Residuals)` | **0 处继承** |
| `Residuals` 出现次数 | 仅 5 次：1 注释 + 2 定义 + 2 导出 |
| `main.py` 的 `--mode inf` | 只调无约束的 `model.sample()`，不走 PCFM |

由此确认：`pcfm/constraints.py` 是「论文附录 D 约束表的代码化」，但**把它接到采样器上的那层没公开**。

**同时发现两处真实 bug**：
1. `ffm_sampler.py:36` 向 `fast_project_batched` 传 4 个关键字，`pcfm_sampling.py:17` 一个都不接
2. 定义处要求 `(B,n)`，调用方传 `(B,nx,nt)`

**对策**：写 `pcfm_compat.py`（约 15 行有效逻辑），只做适配，不动算法。

## 阶段 2：第一次跑通与三次返工

### 返工 1：评测协议错了

初版用 `test[0]` 的 IC 去约束，却与整个测试集均值比 MMSE —— 两者不是同一解子集，指标无意义。
**修正**：按论文 §4.1，固定一个留出 IC，与"同 IC、不同 ν"的解族比较。

### 返工 2：消融被抽样噪声淹没

同一配置两次给出 MMSE **0.481** 与 **0.155**（差 3 倍）。
原因：每个配置重新抽 GP 初始噪声，等于换了题目在比分数。
**修正**：所有配置共用同一批初始噪声（配对比较）。修正后同一配置复跑结果**逐位相同**。

### 返工 3：模型尺度与数据尺度不匹配

最初用标准正态做先验，而 Heat 数据的 std 只有 0.32 → FFM 要压缩 3 倍，短训练完全不收敛。
改用官方的 Matérn GP 先验后正常。

## 阶段 3：性能剖析（决定了能否跑得动）

| 现象 | 数据 |
|---|---|
| 首轮 batch=256 训练 | **13.9 s/步**，峰值 24.5 GiB → 超出 16 GiB，实为显存抖动 |
| batch=128 | 1.40 s/步，12.3 GiB |
| **batch=64** | **0.50 s/步，6.2 GiB** ← 时间效率最高 |
| `num_workers=0` | 1.52 ms/batch |
| `num_workers=4` | 8.10 ms/batch |
| `num_workers=16` | **68 ms/batch（慢 45 倍）** |

**结论**：官方 `main.py` 的 `num_workers=16` 是面向 Linux 集群的配置；
Windows 用 spawn，每个 worker 重导入 torch/gpytorch/neuralop，纯属负优化。
Heat 数据 `__getitem__` 只需 0.018 ms（`sin`/`exp` 现算，不读盘），单进程远优于多进程。

最终训练配置：**batch 64 / num_workers 0 / 20000 步**，实测 0.70 s/步，约 3.9 小时。

## 阶段 4：对齐论文设定（重要修正）

初版用 seed 随机取留出 IC 的 φ。**重读附录 B.1 后发现论文明确写死 φ = π/4**：

> "During constrained sampling, we restrict to the same initial condition by fixing φ = π/4."

同时附录 D.3 给出约束矩阵形式（式 21），与官方 `Residuals.full_residual_heat` 完全一致。

**修正**：所有评测改为 φ = π/4，参考族 16→32 条。

对齐后与论文的吻合度显著提升（CE(IC)：vanilla 700 vs 论文 579；PCFM 0 vs 0）。

## 阶段 5：CE 的量级来源（实测诊断）

对投影后的输出逐样本测量残差：

| | PCFM | vanilla |
|---|---|---|
| ‖IC 残差‖₂ | **0.0000e+00** | 4.32 |
| ‖CL 残差‖₂ | 3.97e-07 | 3.92e-02 |

**为何 IC 精确为 0**：IC 约束在雅可比中是单位行，投影把它直接写成目标值，float32 下逐位相等。
**为何 CL 不是 0**：CL 是 100 项求和 × dx，误差随项数累积，停在 3.97e-07 ≈ 3.3× float32 eps。

**附带发现**：Heat 的 IC 是 $\sin(x+\phi)$，整周期积分为 0，所以论文式 (10) 的守恒质量 $\int u\,dx=0$
本身是零。该约束等价于"空间均值恒为零"——对未训练模型也不算苛刻，因此区分度主要来自 IC 而非 CL。

## 阶段 6：改善倍数的稳定性检验

同一噪声库、同一 IC、只变 checkpoint（φ=π/4）：

| ckpt | vanilla MMSE | PCFM MMSE | 倍数 |
|---|---|---|---|
| 2000 | 5.464 | 0.589 | 9.3 |
| 6000 | 6.903 | 0.210 | 32.9 |
| 10000 | 3.528 | 0.047 | 75.4 |
| 14000 | 4.423 | 0.021 | 206.2 |
| 20000 | 4.700 | 0.042 | 112.1 |

**结论**：改善倍数**不是稳定常数**，随训练单调放大后在宽区间抖动（均值 87，范围 9–206，变异系数 79%）。
原因是 vanilla 的 MMSE 全程停在 3.5–6.9（其误差主要由"与指定 IC 的偏离"主导，训练无法消除），
而 PCFM 一路降到 0.02–0.04。

**换成 IC 维度也不是常数**：6 个 φ 上倍数范围 [3.8, 49.3]，变异系数 69%。
波动几乎全部来自 vanilla（23×），PCFM 只波动 4.8×。

**因此报告里不写单点倍数，写区间与中位数；CE 则单独报告，因为它在 12 次测量中稳定在 3–5×10⁻⁵。**

## 阶段 7：补充训练（进行中）

论文总样本量 256×20000 = 5.12 M；本次 64×20000 = 1.28 M（25%）。
为实现样本量对齐，从 `heat_20000.pt` 续训 60000 步（batch 64 → 再 3.84 M 样本，累计 5.12 M）。
预计约 11.7 小时，每 5000 步存盘。

### 续训是否重放旧数据（专门验证）

数据集的 $(\nu,\phi)$ 来自 Python `random`。检验结果：

| 检验 | 结果 |
|---|---|
| 同一 seed 抽两次（对照） | 2000/2000 完全相同 |
| seed 42 → 20042 | 同位置相同 0/2000，$(\nu,\phi)$ 组合重叠 0 |

即：**若沿用同一 seed 续训，会原样重放**。已改为 `seed_all(seed + resume_step)`。

附带说明：已完成的 20000 步当时**未种子 `random`**（只种了 torch），
因此那段数据流不可复现，但不影响正确性——分布仍是 $\nu\sim U(1,5),\ \phi\sim U(0,\pi)$。

## 阶段 8：与论文的差异汇总

| 项 | 论文 | 本次 | 原因 |
|---|---|---|---|
| batch_size | 256 | 64 | 16 GiB 显存上限 |
| 总样本量 | 5.12 M | 1.28 M（续训后 5.12 M） | 同上 |
| num_workers | 16 | 0 | Windows 多进程负优化 |
| 学习率调度 | ReduceLROnPlateau | CosineAnnealing → **已知偏差** | 自写训练循环所致，见下 |
| FPD | 报告 | 未测 | Poseidon 权重未公开 |
| 生成样本数 N | 未说明 | 16 / 32 | 论文未给出，取可比规模 |

### 已知偏差：训练循环

本次 `run_heat_official.py::cmd_train` 的**训练循环由本仓库实现**，
而官方 `scripts/training/main.py` 是存在的。两者逻辑相同，但：

- 官方配置 `scheduler.type: plateau`（ReduceLROnPlateau, factor 0.5, patience 10, min_lr 1e-4）
- 本次使用 CosineAnnealingLR

**这是实质差异**，训练动力学因此与论文不同。
官方脚本在 Windows 下需改 `num_workers`、另装 `easydict`，故当时未直接采用。
后续如需完全对齐，应以 `main.py` 重训。
